## Problem 4: Backpacking

Norman walks through `N` towns in order. Getting from town `i` to town `i+1` takes `D[i]` days, he eats one can per day, and his pack holds at most `K` cans.

Town `i` sells cans for `C[i]` dollars each. We want to minimise how much Norman spends.

The obvious approach is a DP over `(town, cans currently held)`, which is `O(N*K)`. With `K` going up to a million, that's not exactly going to end well.

The solution is greedy, and the trick that makes it work is allowing yourself to **un-buy** cans.

At every town, fill the pack completely at the current price. That sounds wrong because you'll sometimes be carrying cans that were more expensive than what you can buy later.

When you reach a cheaper town, just refund the expensive cans still in your pack and buy them again at the cheaper price. Since cans are interchangeable, this is effectively just correcting the decision we made earlier.

We keep the pack as a deque of `[price, quantity]` blocks.

The important invariant is that prices strictly increase from the front to the back. When we arrive at a town with price `c`, we remove blocks from the back while their price is `>= c`, refunding their cost as we go.

Eating works nicely with the same structure. We eat from the front, which contains the cheapest cans. That means the cans left in the pack are always the more expensive ones, exactly the cans we might want to refund later.

```python
from collections import deque

n, k = map(int, input().split())

d = list(map(int, input().split()))
c = list(map(int, input().split()))

backpack = deque()

answer = 0
current = 0

for i in range(n - 1):
    currentprice = c[i]

    # Refund anything we're holding that costs at least as much as here.
    while backpack and backpack[-1][0] >= currentprice:
        price, qty = backpack[-1]
        answer -= price * qty
        current -= qty
        backpack.pop()

    # Fill the pack at the current price.
    rem = k - current
    backpack.append([currentprice, rem])
    answer += currentprice * rem
    current += rem

    # Walk to the next town, eating from the cheapest end.
    days = d[i]

    while days > 0:
        price, qty = backpack[0]

        if qty <= days:
            current -= qty
            backpack.popleft()
            days -= qty
        else:
            backpack[0][1] -= days
            current -= days
            days = 0

# We've reached town N, so refund anything left over.
while backpack:
    price, qty = backpack[-1]
    answer -= price * qty
    current -= qty
    backpack.pop()

print(answer)
```


Because we fill the pack at every town, Norman can arrive at town `N` with cans he never actually eats. We've charged him for those cans, so they need to be refunded.

Each town adds at most one block, so there are at most `N` blocks in the deque. Every iteration of the inner `while` loops either removes a block or finishes the current operation, so the total work is **`O(N)` amortised**.

The constraints also give `C[i] <= 20`. That's a very small price range, so there is also a counting-based solution over the 20 possible prices.

The deque solution doesn't need that bound at all, though. It's one of those constraints that's worth noticing, even if you don't actually use it.

## Problem 5: Tennis Robot II

There are `N` bins and `M` instructions.

Instruction `j` takes a ball from bin `A[j]` and puts it into bin `B[j]`. The robot repeats the instruction list forever, but crashes as soon as it's told to take a ball from an empty bin.

We need to find how many instructions it completes.

Obviously, we can't just simulate the robot. `X[i]` can be up to a million, and the answer can be around `M` times that, so a straightforward simulation could take around `10^11` operations.

The key observation is that **every pass through the instruction list is identical**.

So we can process one complete cycle and record two things for every bin:

* **`currentchange[i]`**: the net change to the bin after one full cycle.
* **`worst[i]`**: the lowest the bin's running change gets during that cycle.

A bin can only reach a new minimum immediately after a ball is taken from it, so we only need to update `worst` when processing `A[j]`.

Once we know those two values, we can skip entire cycles.

After `t` complete cycles, bin `i` contains

`X[i] + t * currentchange[i]`.

During the next cycle, its lowest value is

`X[i] + t * currentchange[i] + worst[i]`.

So we can work out when each bin will first become empty and take the minimum across all bins.

There are three cases:

1. **The robot crashes during the first cycle.**
   We catch this while processing the cycle.

2. **Every `currentchange[i]` is zero.**
   The state after every cycle is identical to the state before it. Since the first cycle didn't crash, the robot will never crash. Print `FOREVER`.

3. **At least one bin is draining.**
   Since every instruction removes one ball and adds one ball, all the net changes sum to zero. If they're not all zero, at least one must be negative.

   We can skip forward to the last safe cycle, then simulate one final cycle normally to find the exact instruction where the robot crashes.

```python
n, m = map(int, input().strip().split())

x = [0] + list(map(int, input().strip().split()))  # 1-indexed

a, b = [], []

for _ in range(m):
    ai, bi = map(int, input().strip().split())
    a.append(ai)
    b.append(bi)

answer = 0

worst = [0] * (n + 1)
currentchange = [0] * (n + 1)

confirmed = False

# One cycle, recording net drift and the worst dip per bin.
for i in range(m):
    currentchange[a[i]] -= 1
    worst[a[i]] = min(worst[a[i]], currentchange[a[i]])

    currentchange[b[i]] += 1

    if currentchange[a[i]] < -x[a[i]]:
        answer = i
        confirmed = True
        break

# No drift anywhere means the state is periodic.
if not confirmed and currentchange.count(0) == n + 1:
    answer = -1
    confirmed = True

# Skip ahead to the last cycle that survives, then simulate it.
if not confirmed:
    amttoskip = 10 ** 20

    for i in range(1, n + 1):
        if currentchange[i] < 0:
            num = x[i] + worst[i]
            den = -currentchange[i]

            amttoskip = min(amttoskip, num // den + 1)

    answer = amttoskip * m

    x = [
        x[j] + currentchange[j] * amttoskip
        for j in range(n + 1)
    ]

    for i in range(m):
        x[a[i]] -= 1
        x[b[i]] += 1

        if x[a[i]] < 0:
            answer += i
            break

print("FOREVER" if answer == -1 else answer)
```

The whole thing takes **`O(N + M)`** time. We process the instructions a couple of times and the bins once, regardless of how huge the final answer is.

### Checking it by hand

Sample 3 is the interesting one because it actually uses the skipping logic.

We start with five bins:

`3 2 6 4 5`

and the instructions:

`(1,5) (4,3) (2,3) (4,2)`

After one complete cycle, the net changes are:

`[-1, 0, +2, -2, +1]`

and the worst dips are:

`[-1, -1, 0, -2, 0]`

Bin 1 loses one ball per cycle. Its starting value is 3 and its worst dip is `-1`, so:

`(3 - 1) // 1 + 1 = 3`

cycles can be skipped according to that bound.

Bin 4 is more interesting. It loses two balls per cycle and has a worst dip of `-2`:

`(4 - 2) // 2 + 1 = 2`

So bin 4 is the first one that can cause a crash.

That means two complete cycles are safe, giving us:

`2 * 4 = 8`

instructions.

After applying the drift twice, the bins contain:

`1 2 10 0 7`

Now we replay the next cycle normally.

Instruction 0 takes from bin 1, which is fine.

Instruction 1 tries to take from bin 4, which is empty.

So the robot gets another instruction in before crashing:

`8 + 1 = 9`

which matches the sample.
