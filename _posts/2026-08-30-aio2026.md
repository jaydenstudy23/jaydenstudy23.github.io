## Problem 1: Jump for Platforms

I don't remember any of the subtasks, which is probably fine.

All it asks for is the highest difficulty between consecutive jumps. So compare each adjacent pair and keep a running maximum.

```python
n = int(input())
p = list(map(int, input().split()))

answer = 0

for i in range(1, n):
    answer = max(answer, p[i] - p[i - 1])

print(answer)
```

## Problem 2: IGM

This one asks whether there's a starting point that makes everything increasing.

Reframed: a circular sequence can be made strictly increasing by choosing an appropriate starting point exactly when **one** adjacent pair fails `a[i] > a[i-1]`. That single failure is the wrap-around point, and it becomes the start.

So check every adjacent pair (including the pair that wraps from the last element to the first). If exactly one fails, the answer is `YES`.

Checking every starting point individually gets you the small-cases subtask.

```python
n = int(input())
a = list(map(int, input().split()))

# greater[i] means a[i] > a[i-1]
greater = [False] * n

greater[0] = a[0] > a[n - 1]

for i in range(1, n):
    if a[i] > a[i - 1]:
        greater[i] = True

if greater.count(True) == n - 1:
    print("YES")
else:
    print("NO")
```

## Problem 3: Discount Destinations

You're given an array of prices, one per day of a trip. Each day you pay that day's amount, but you can't spend more than `d` across any window of `k` days.

The maths is simple enough that I won't cover it. The part worth getting right is the budgeting.

Keep a running total of what you've spent inside the current window — the code calls it `count`. Simulate the first `k` days with nothing leaving the window, then on each later day `i`, subtract `a[i-k]` before spending.

The catch is that what you *spent* on a day isn't always what the day *cost*, because the budget can cut you off partway. Store the actual amount spent per day in its own array, otherwise the sliding window drifts.

```python
n, k, d = map(int, input().split())
a = list(map(int, input().split()))

answer = 0
count = 0
spent = [0] * n

for i in range(k):
    if count + a[i] > d:
        spent[i] = d - count
        answer += d - count
        count += d - count
    else:
        spent[i] = a[i]
        answer += a[i]
        count += a[i]

for i in range(k, n):
    count -= spent[i - k]

    if count + a[i] > d:
        spent[i] = d - count
        answer += d - count
        count += d - count
    else:
        spent[i] = a[i]
        answer += a[i]
        count += a[i]

print(answer)
```

## Problem 4: Sunday Drive II

You're driving through neighbourhood `V` and want the music as loud as possible. House `i` has a noise tolerance `v[i]`, so you can't drive past it with volume above `v[i]`. At each house you can raise the volume by 1, lower it by 1, or leave it alone.

Constraints are `N <= 200000` and `v[i] <= 10000`.

The approach is greedy: push the volume up whenever you can, and take a simple `-1` step down when that's enough. When a `-1` isn't enough — when the next house needs the volume much lower than it currently is — walk backwards and lower the earlier houses until the descent works out.

`answers` holds the volume at each house, and the result is its sum.

I don't have a clean argument for why this runs in time. I assume it's amortised: the backwards fix can only lower values that were raised earlier, so the total work is bounded by the total amount of raising. It passed, anyway.

```python
n = int(input())
v = list(map(int, input().split()))

answers = [0] * n
vol = 0


def fix(x, i):
    temp = x
    j = i - 1

    while temp < v[j]:
        temp += 1
        answers[j] = min(answers[j], temp)
        j -= 1


for i in range(n):
    if v[i] > vol:
        vol += 1
        answers[i] = vol
    elif v[i] == vol:
        answers[i] = vol
    elif v[i] == vol - 1:
        vol -= 1
        answers[i] = vol
    elif v[i] < vol - 1:
        fix(v[i], i)
        vol = v[i]
        answers[i] = vol

print(sum(answers))
```

## Problem 5: Prime Minister

You're the prime minister of a country with `N` citizens and you have `k` dollars to hand out. Maximise the median wealth. The wealths are given to you already sorted.

Two observations.

**Keep half the population in poverty.** Since the array is sorted, only citizens from the median onward can affect the median. Money spent below the median is wasted.

More precisely: suppose we raise citizen `A` instead of citizen `B`, where `B` starts with at least as much as `A`. Raising `B` to the same final wealth costs no more, so swapping `A` for `B` never makes things worse. So we can ignore the lower half entirely.

**The answer is monotonic.** If a median of `x` is achievable, so is `x-1`, `x-2`, and so on — reaching a lower target only ever needs less money.

Monotonicity gives us binary search, and the poverty observation gives us the check function: to reach median `x`, every citizen in the upper half below `x` needs topping up to `x`. Sum those gaps and compare against `k`.

```python
n, k = map(int, input().split())
a = list(map(int, input().split()))

newl = n - (n // 2)
b = [a[i] for i in range(n // 2, n)]


def check(x):
    gaps = [0] * newl

    for i in range(newl):
        gaps[i] = max(0, x - b[i])

    return sum(gaps) <= k


l = 0
r = 10 ** 12
answer = -1

while l <= r:
    mid = (l + r) // 2

    if check(mid):
        answer = mid
        l = mid + 1
    else:
        r = mid - 1

print(answer)
```

## Problem 6: Mundane Square

You're given the row sums and column sums of a "mundane square" and have to reconstruct it. Every cell is capped at `k`.

The input is:

```
N k          (N = grid size, k = max cell value)
R            (row sums)
C            (column sums)
```

Subtasks from memory — all of them except the full solution have `N <= 100` plus something else I've forgotten:

* **ST1** — `r[i] = 1` for all `i`
* **ST2** — `k` is very large
* **ST3** — `k = 1`
* **ST4** — small cases
* **ST5** — full solution, `N <= 1000`

Honestly, I have no idea what the full solution is.

**Subtask 1** is easy: every row sum is 1, so each row is a single 1 somewhere. Walk along the columns filling in ones from left to right, moving to the next column once its sum is used up.

**Subtask 2** has no meaningful cap, so cells can be anything. Greedily fill top to bottom, left to right — dump as much of each row's remaining sum into the current column as that column will take, then move on.

I tried a greedy for **subtask 3** and it didn't work. I won't comment on the rest since I didn't get them.

Both cases start with the same feasibility check: if the row sums and column sums don't add to the same total, no square exists.

```python
n, k = map(int, input().split())

rows = list(map(int, input().split()))
cols = list(map(int, input().split()))


def fail():
    print("NO")
    exit()


# Subtask 1: every row sum is 1.
if rows.count(1) == n:
    if sum(cols) != sum(rows):
        fail()

    rowpointer = 0
    colpointer = -1
    construction = [0] * n
    cnt = 0

    while rowpointer != n:
        while cnt == 0 and colpointer <= n:
            colpointer += 1
            cnt += cols[colpointer]

        while cnt > 0:
            construction[rowpointer] = colpointer + 1
            cnt -= 1
            rowpointer += 1

    print("YES")

    for i in range(n):
        x = [0] * n
        x[construction[i] - 1] = 1
        print(*x)

    exit()

# Subtask 2: k is effectively unbounded.
if k == 1000000000:
    if sum(cols) != sum(rows):
        fail()

    temp = [i for i in cols]
    construction = [[0] * n for i in range(n)]

    for i in range(n):
        rem = rows[i]

        for j in range(n):
            # Too little or exactly enough: this column finishes the row.
            if rem <= temp[j]:
                construction[i][j] += rem
                temp[j] -= rem
                break

            # More than fits: fill the column and carry on.
            if rem > temp[j]:
                construction[i][j] = int(temp[j])
                rem -= temp[j]
                temp[j] = 0

    print("YES")

    for i in range(n):
        print(*construction[i])

    exit()
```
